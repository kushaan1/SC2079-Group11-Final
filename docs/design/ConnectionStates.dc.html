WHAT C.8 ACTUALLY TESTS
A supervisor hits Disconnect on the AMD tool, then Connect again. The app must not hang in between, and must come back on its own — no taps.
Because the peer initiates the second connection, a client-only retry loop fails this. We have to be listening.
SO BOTH ROLES RUN AT ONCE
CLIENT
connect() → RPi
SERVER
accept() ← AMD
First to establish wins; the loser is cancelled. Client retries back off 1s → 2s → 4s → 5s and never give up.
Every state above is a value of one StateFlow<ConnectionState> that outlives the screen — so rotating the tablet mid-reconnect changes nothing.
